# CAD → BIM 資料流技術筆記

從 2D CAD 圖面到 3D 模型交付，中間有三個容易出事的環節：**資料怎麼被提取**、**提取後長什麼樣子**、以及**交付後客戶說對不上時怎麼查**。

這個 repo 是我對這三個環節的整理，來自十年機電（MEP）建築資訊建模（BIM）整合的現場經驗，以及把這些經驗轉成自動化流程時踩過的坑。

## 三份文件

| 文件 | 主題 | 解決什麼問題 |
|---|---|---|
| [01 模型驗收與根因分析](docs/01-model-acceptance.md) | 治理 | 客戶說「模型跟圖面對不起來」時，用什麼順序查才不會浪費時間 |
| [02 建築構件資料結構](docs/02-element-data-structure.md) | 設計 | 把 Column / Wall / Slab 組成結構化資料傳給下游 3D 模組，類別架構怎麼切 |
| [03 CAD 與 Revit 的資料提取差異](docs/03-cad-vs-revit-extraction.md) | 實作 | 為什麼 AutoCAD 的提取程式總是漏元素、拋例外，換成 Revit 又為什麼不會 |

## 三者的關係

```
         ┌─────────────────────────────────────────┐
         │  2D CAD 圖面 (.dwg)                      │
         └────────────────┬────────────────────────┘
                          │
                    【03】提取
                    圖層規則、圖塊遞迴、例外保護
                          │
                          ▼
         ┌─────────────────────────────────────────┐
         │  結構化資料 (JSON)                        │
         └────────────────┬────────────────────────┘
                          │
                    【02】資料結構
                    共用屬性 vs 幾何資訊、key mapping 解耦
                          │
                          ▼
         ┌─────────────────────────────────────────┐
         │  3D 模型交付                              │
         └────────────────┬────────────────────────┘
                          │
                    【01】驗收
                    版次溯源、疊圖比對、時間節點回溯
                          │
                          ▼
                    客戶確認 / 爭議處理
```

一個貫穿三份文件的觀點：**CAD 的資料本身不帶意義，意義是人事先用圖層與命名規則賦予的**。這個前提決定了提取邏輯必須防禦性地寫（03）、資料結構必須把「資料內容」與「輸出命名」分層（02），也決定了驗收爭議大多不是技術問題而是版次管理問題（01）。

## 程式碼

[`building_elements.py`](building_elements.py) 是 02 的可執行實作，包含類別定義與 JSON 輸出示範。以模擬資料執行：

```bash
python building_elements.py
```

## 說明

- 文件中的流程與方法為抽象層次的實務整理，不含任何特定專案、客戶或公司的資訊。
- 構件參數僅為示意，實際實作時幾何參數的數量與型別會依圖面規範、座標系定義及下游模組接收格式而有所不同。
